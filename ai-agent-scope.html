Section 01
AI Agent 是什麼、範疇到哪裡
先對齊定義，再談應用；避免把「聊天機器人」與「可執行任務的 Agent」混為一談
💡
一句話定義：AI Agent = 大型語言模型（判斷）＋ 工具呼叫（行動）＋ 記憶與資料（上下文）＋ 編排與權限（治理）。 它與傳統自動化最大的差別是：流程不需要事先窮舉所有分支，Agent 會依當下情境自行決定下一步該呼叫哪個工具。
CAPABILITY 01
理解與判斷
讀懂非結構化輸入 — 客戶訊息、報表、合約、廣告素材、會議逐字稿，並判斷該做什麼。這是 RPA 做不到的部分。
CAPABILITY 02
呼叫工具行動
透過 API／MCP 實際操作系統：查 GA4、拉 Meta 成效、寫進 Google Sheet、開工單、寄信、上稿。有行動能力才叫 Agent。
CAPABILITY 03
記憶與知識
接上公司知識庫（RAG）與歷史紀錄，讓輸出符合公司規範、品牌語氣與過往決策，而不是通用答案。
CAPABILITY 04
編排與治理
多步驟任務的流程控制、權限邊界、人工審核關卡（Human-in-the-loop）與稽核軌跡。決定能不能真的上線。
三種型態 — 不要一開始就做全自主 Agent
Assistive / Semi-auto / Autonomous
型態運作方式適合場景風險建議比重
L1 輔助 人下指令、Agent 產出草稿，人決定要不要用。不直接寫入系統。 文案撰寫、報告初稿、資料摘要、翻譯、程式碼輔助 低 先做，佔 60%
L2 半自動 Agent 自行完成多步驟任務，但關鍵動作（發送／上稿／付款）需人工按下確認。 週報自動產出、廣告成效診斷、進稿前置作業、客訴分類與回覆草稿 中 主力，佔 35%
L3 自主 在明確規則與預算上限內自行決策並執行，事後稽核。 異常監控告警、預算再分配、庫存補貨提醒、排程型例行作業 高 限縮，佔 5%

Section 03
導入優先級
以「價值 × 可行性」排序，先做右上角：價值高、難度低
🎯
排序原則：資料已在手、流程已標準化、錯了可以救的場景最先做。 價值（1–10）看省下的工時與決策品質；可行性（1–10）看資料可得性、系統可串接程度與錯誤成本。

Section 04
技術架構與能力層
同一套底層能力支撐所有部門場景，避免每個需求各做一套
🏗️
原則：一次投資、多處複用。資料層與工具層是共用地基（做一次）， 上層的部門場景只是不同的提示詞、流程與權限組合（做很多次、很快）。
